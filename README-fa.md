# cbm-http-bridge — پل HTTP برای codebase-memory-mcp

یک **پل Streamable HTTP احراز‌شده** برای **codebase-memory-mcp** — سرور MCP متن‌بازی که یک کدبیس را به‌صورت گراف دانش ایندکس می‌کند — روی ماشینی داخل یک شبکه‌ی خصوصی [Tailscale](https://tailscale.com).

پل، سرور بالادستی را به‌صورت یک **پروسه‌ی فرزند stdio** روی همان ماشین اجرا می‌کند و آن را به شکل یک اندپوینت MCP از نوع Streamable HTTP (بدون state، روی `POST /mcp`) دوباره عرضه می‌کند؛ با احراز Bearer اجباری، بایند فقط روی IP تیل‌نت میزبان، لاگ ممیزی برای هر فراخوانی، و یک DENY list زنده برای ابزارهای مخرب.

> English: [README.md](README.md)

## چرا ساخته شد؟

ایجنت‌های ابری (و هر کلاینت بیرون تیل‌نت شما) **مستقیم به یک سرویس tailnet-only نمی‌رسند**؛ آدرس‌های Tailscale از اینترنت عمومی route نمی‌شوند. راه معمول — دادن دسترسی SSH به ایجنت — خیلی پهن‌تر از نیاز کار است: شل یعنی دسترسی به همه‌چیز.

این پل یک لایه‌ی عمداً باریک جلوی گراف کد است:

- **فقط خواندن / کوئری + ایندکس.** کلاینت ریموت می‌تواند پروژه‌های ایندکس‌شده را لیست کند، گراف کد را جست‌وجو و پیمایش کند و ایندکس‌کردن را تریگر کند — هیچ‌چیز دیگر.
- **ابزارهای مخرب در خود پل رد می‌شوند**، هرچه کلاینت بخواهد (DENY list پایین).
- **یک توکن، یک پورت، یک اینترفیس** (کارت شبکه‌ی تیل‌نت) — سطح حمله‌ای خیلی کوچک‌تر از شل.

کاربرد اصلی: یک ایجنت ناظر روی یک VM ابری بتواند از گراف کدی که روی مک دولوپر زندگی می‌کند کوئری بگیرد، بدون اینکه آن مک به او SSH داده باشد.

## چطور کار می‌کند؟

```
کلاینت MCP ریموت ──HTTP + Bearer──▶ bridge.mjs ──stdio──▶ codebase-memory-mcp
 (VM ابری، تیل‌نت)                    (همین ریپو)              (پروسه‌ی فرزند، لوکال)
```

- یک پروسه‌ی فرزند stdio زنده نگه داشته می‌شود و `tools/list` و `tools/call` به آن فوروارد می‌شوند.
- سمت پایین‌دستی **stateless** است: برای هر درخواست HTTP یک سرور و ترنسپورت تازه ساخته می‌شود (Streamable HTTP، پروتکل `2025-03-26`).
- هر درخواست باید `Authorization: Bearer <token>` داشته باشد؛ غیر از این `401` می‌گیرد (و در لاگ ممیزی ثبت می‌شود).
- `GET /healthz` (آن هم پشت احراز) `{"ok": true}` برمی‌گرداند.

### DENY list

این ابزارهای بالادستی در پل به‌سختی رد می‌شوند و به کلاینت خطای MCP برمی‌گردد:

| ابزار | چرا |
|---|---|
| `delete_project` | پروژه‌ی ایندکس‌شده را نابود می‌کند |
| `manage_adr` | رکوردهای تصمیم معماری می‌نویسد |
| `ingest_traces` | محتوای تریس داخل گراف می‌نویسد |

مجموعه‌ی `DENIED` در `bridge.mjs` قابل ویرایش است، ولی قبل از بازکردن هر write از این لایه‌ی ریموت، خوب فکر کنید.

### لاگ ممیزی

برای هر رویداد یک خط به `audit.log` کنار `bridge.mjs` اضافه می‌شود (قابل تغییر با `CBM_BRIDGE_AUDIT_LOG`). فقط زمان، نوع رویداد و **نام ابزار** ثبت می‌شود — هرگز محتوای آرگومان‌ها.

## نصب و اجرا

نیازمندی: Node.js ‏≥ 18 و نصب `codebase-memory-mcp` روی میزبان (یا تنظیم `CBM_BIN` روی مسیرش).

```bash
git clone <this-repo> cbm-http-bridge
cd cbm-http-bridge
npm install

export CBM_BRIDGE_TOKEN="$(openssl rand -hex 32)"   # راز نگهش دارید
export CBM_HTTP_HOST="127.0.0.1"                     # تست محلی
npm start
```

### کانفیگ (متغیر محیطی)

| متغیر | پیش‌فرض | کاربرد |
|---|---|---|
| `CBM_BRIDGE_TOKEN` | — (اجباری) | توکن Bearer کلاینت‌ها. بدون آن پل **اصلاً بالا نمی‌آید**. (`CBM_HTTP_TOKEN` هم به‌عنوان نام قدیمی پذیرفته می‌شود.) |
| `CBM_HTTP_HOST` | `127.0.0.1` | آدرس بایند. برای سرویس به کلاینت‌های تیل‌نت، IP تیل‌نت میزبان (`100.x.x.x`) را بگذارید. **هرگز `0.0.0.0` نگذارید.** |
| `CBM_HTTP_PORT` | `8321` | پورت |
| `CBM_BIN` | `codebase-memory-mcp` (از PATH) | دستور سرور stdio بالادستی |
| `CBM_BRIDGE_AUDIT_LOG` | `./audit.log` کنار `bridge.mjs` | مسیر لاگ ممیزی |

### اجرای دائمی با launchd (مک)

فایل `launchd/com.example.cbm-http.plist.example` یک LaunchAgent آماده‌ی پرکردن است: مقادیر `__PLACEHOLDER__` (مسیر خانه، مسیر Node، IP تیل‌نت، توکن، مسیر باینری بالادستی) را با مقادیر خودتان عوض کنید، فایل را به‌صورت `~/Library/LaunchAgents/com.example.cbm-http.plist` ذخیره کنید، رویش `chmod 600` بزنید (توکن داخلش است) و با `launchctl load` فعالش کنید.

### تست دود

```bash
CBM_BRIDGE_TOKEN=<your-token> python3 test_from_vm.py http://<tailnet-ip>:8321/mcp
```

تست `initialize` می‌کند، لیست ابزارها را می‌گیرد و یک کوئری خواندنی واقعی (`list_projects` اگر موجود باشد) اجرا می‌کند.

## مدل امنیتی

- **شبکه**: پل دقیقاً روی یک آدرس بایند می‌شود — در استقرار واقعی، IP تیل‌نت میزبان — پس از LAN و اینترنت در دسترس نیست. ACLهای Tailscale محیط بیرونی‌اند؛ این پل محیط درونی است.
- **احراز**: یک توکن Bearer بلند و تصادفی، روی هر درخواست (حتی `/healthz`) چک می‌شود. توکن ست نشده باشد، پروسه به‌جای سرویس‌دادن بدون احراز، خارج می‌شود.
- **اختیار**: حتی با توکن معتبر، ابزارهای DENY list رد می‌شوند. لو رفتن توکن یعنی دسترسی خواندن/کوئری/ایندکس به گراف کد شما — که خودش حساس است؛ چرخاندن توکن = ری‌استارت پل با توکن تازه.
- **کمینه‌سازی داده**: لاگ ممیزی فقط نام ابزار و زمان را نگه می‌دارد.
- **پوشش‌نداده‌ها**: TLS (ترافیک روی تیل‌نت رمزنگاری‌شده می‌رود؛ این اندپوینت را بیرون تیل‌نت عرضه نکنید)، توکن جدا برای هر کلاینت، و rate limiting. اگر لازمشان دارید، پل را پشت یک ریورس‌پراکسی تحت کنترل خودتان — داخل همان تیل‌نت — بگذارید.
